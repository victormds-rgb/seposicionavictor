# UI_UX.md
### SEPosicionaVictor — Experiência de Uso

## 1. Filosofia da Interface

Menos cliques, sempre. Nunca mostrar complexidade desnecessária. Contexto acima de menus. IA como assistente, nunca protagonista. Tudo começa pela Inbox. Sempre permitir intervenção humana. Interface orientada à tomada de decisão, não à exibição de dado. Silêncio é uma feature — se nada precisa de atenção, a interface não inventa algo para mostrar.

## 2. Perfil do Usuário

Único usuário: Victor Sousa. Fundador solo de agência, não desenvolvedor, alterna reuniões presenciais, produção de conteúdo e gestão de projetos. Usa iPhone com frequência. Objetivos: saber o que fazer na semana; não perder informação de reunião; manter ritmo de Build Log/conteúdo; não deixar cliente ruim passar despercebido; sentir que o sistema segura a consistência da marca mesmo sob sobrecarga. Limitações: caixa apertado, sem equipe, tempo fragmentado, tendência a recuar sob frustração — a interface tolera hiatos de uso sem punir.

## 3. Jornada Diária

Manhã: Dashboard mostra o que importa hoje (agenda, alertas, pendências da Inbox). Durante o dia: captura contínua na Inbox (voz, texto, foto) sem decidir categoria no momento. Meio do dia: revisão assistida das sugestões de classificação. Tarde: produção de conteúdo guiada pela rotina semanal. Fim do dia: checagem leve de alertas, sem checklist obrigatório de fechamento.

## 4. Navegação Global

Dashboard, Inbox, Agenda, Pipeline Comercial, Clientes, Projetos, Conteúdo (inclui Cases e Build Logs como abas internas), Conhecimento, Brand Intelligence, Missões (quando existir), Configurações.

## 5. Dashboard

Objetivo: responder "o que preciso saber e decidir agora" em um único olhar. Mostra: agenda do dia, alertas ativos ordenados por urgência, contagem de pendências da Inbox, desvio de distribuição de pilares (só se relevante). Nunca mostra métrica de vaidade ou histórico sem propósito de decisão.

## 6. Inbox Universal

Fluxo: captura (qualquer tipo de entrada, sem pergunta de categoria) → processamento (indicador leve se exigir transcrição/OCR) → sugestão de destino com justificativa curta → confirmação (aceitar/editar/descartar) → destino visível no histórico. Filtros por status, tipo, origem. Busca sobre conteúdo já extraído.

## 7. Pipeline Comercial

Lead → Qualificação (tela única, campos do Cap. 7.1) → Agendamento (Google Calendar) → Reunião → captura na Inbox ao encerrar → Conversão (árvore de decisão em 3 passos guiados) → Cliente → Projeto pré-preenchido, exigindo só confirmação de desculpa/custo.

## 8. Agenda

Visão semanal padrão. Preparar reunião: histórico do Cliente/Projeto visível automaticamente. Revisar contexto: último Case/Build Log relacionado visível. Encerrar reunião: atalho imediato para captura na Inbox.

## 9. Projetos

Status visível + barra de progresso dos 6 campos do case. Prioridade visual conforme classificação do cliente. Build Log mostra frequência recente diretamente. Transição direta para Case quando "pronto para case".

## 10. Conteúdo

Toda peça nasce de Case, Build Log, ou autônoma, com tema/framework/pilar já sugeridos. Rascunho de IA sempre identificado como rascunho até confirmação explícita. Nunca publica automaticamente em rede social. Histórico navegável por pilar/tema/série/canal, nunca arquivado.

## 11. Conhecimento

Biblioteca de consulta rápida (frameworks, temas, perguntas, analogias). Mostra quais Cases/Conteúdos já usaram um framework. Sem modo tutorial.

## 12. Brand Intelligence

Lista de documentos oficiais com data de sincronização. Indicador simples de status (indexado/desatualizado/erro). Botão único de "sincronizar agora".

## 13. IA

Toda sugestão tem rótulo visual consistente e justificativa curta. Confirmação sempre com aceitar/editar/rejeitar, nunca "ok" único. Confiança mostrada em nível simples (alta/média/baixa), não número técnico. Custo mostrado só em tela de configuração/histórico, nunca no fluxo do dia a dia.

## 14. Alertas

Discretos, agrupados no Dashboard e central de notificações, nunca pop-up intrusivo. Priorização: exige ação > informativo. Reconhecer sem resolver é possível. Histórico sempre consultável.

## 15. Busca Global

Campo único, cobrindo Cases, Projetos, Clientes, Inbox, Documentos, Reuniões, Conteúdo, Conhecimento. Resultados agrupados por tipo.

## 16. Mobile

Deve existir: captura na Inbox, consulta de agenda, revisão de sugestões, alertas. Não deve existir: edição extensa de conteúdo longo, configuração de Brand Intelligence, auditoria trimestral detalhada, qualificação detalhada de lead. Desktop-first: produção de conteúdo, Cases, Conhecimento, Brand Intelligence, Configurações.

## 17. Estados da Interface

Loading (leve, localizado), Erro (mensagem simples + ação), Sem dados (sempre com frase de contexto), Processando IA (distinto de loading comum), Aguardando confirmação humana (visualmente destacado e consistente), Sincronizando (discreto, não bloqueia).

## 18. Princípios Visuais

Hierarquia: decisão acima de informativo. Espaçamento generoso. Legibilidade: texto > ícone em caso de ambiguidade. Densidade baixa a moderada. Cor reservada para sinalizar necessidade de ação, nunca decorativa.

## 19. Experiência dos Agentes (Futuro)

Cada Agent aparece como "colaborador" nomeado e delimitado, no mesmo padrão visual de SugestaoIA. Acionado explicitamente por Victor. Progresso como lista simples de passos. Aprovação segue o mesmo padrão já estabelecido, nunca uma "caixa preta".

## 20. Roadmap Evolutivo da UX

Cresce em: mais tipos de entrada na Inbox (sem nova navegação); mais Bounded Contexts de primeiro nível (só quando têm fluxo de decisão próprio); mais autonomia de IA (sempre dentro do padrão sugestão/confirmação já estabelecido). Critério permanente: se a mudança exige novo modelo mental, está errada.
